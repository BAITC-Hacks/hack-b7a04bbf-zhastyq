# Фронтенд AML MVP

Одноэкранный интерфейс аналитика: загрузка Parquet, топ приоритетов, поиск `gid`, направленный граф и карточка узла. Бэкенд команды — модульный монолит с одним HTTP API.

## Локальный запуск

Используйте Node.js `24.11.0` из `.nvmrc` и npm `11.6.1`. Из каталога `frontend/`:

```bash
npm install && npm run dev
```

Команда поднимает приложение в зелёно-бело-чёрной теме с демонстрационными данными. Для всех 20 участников доступны признаки из топ-листа. Полная карточка и граф подготовлены для gid 1005; для его соседей потоки считаются по показанному срезу с явной подписью. Три слота импорта работают независимо: выбор, перетаскивание, замена, удаление и локальная проверка файлов. В real-режиме файлы отправляются в backend, а после расчёта обновляются граф, топ и карточка. Синтетические результаты в real-режиме не подставляются.

Дизайн-токены находятся в `src/styles/tokens.css` и импортируются первыми в `src/main.tsx`. Файлом владеет агент 1. Агент 2 читает глобальные `--graph-*` и `--role-*` при оформлении графа.

Для воспроизводимой установки по зафиксированному `package-lock.json` можно использовать `npm ci` вместо `npm install`.

## API и mock-режим

Без `.env` приложение запускается в mock-режиме. Для явной настройки скопируйте `.env.example` в `.env`. `VITE_API_MOCK=true` означает работу со статичными синтетическими фикстурами в `src/shared/api/fixtures/`; `false` включает HTTP API по `VITE_API_BASE_URL` (например, `http://127.0.0.1:8000`). Обе переменные читает только API-адаптер. После изменения `.env` перезапустите dev-сервер. Подробная фикстура подготовлена для `gid=1005`. Выбор его соседей сохраняет показанный срез; выбор клиента вне среза показывает известные признаки и отсутствие детализации переводов. Неизвестные суммы отображаются текстом об отсутствии данных, а не нулями.

Действующий HTTP-контракт описан в `../backend/docs/data_contract.md`; общие типы компонентов — в `src/shared/contracts.ts`. Предварительные маршруты из `ARCHITECTURE.md` заменены в адаптере фактическими `/api/analyze`, `/api/analysis`, `/api/nodes/{gid}`.

## Передача работы между агентами

- Агент 1: `AGENT_APP.md` — экран, сценарий, API, mock/real переключатель.
- Агент 2: `AGENT_GRAPH.md` — только `src/features/graph/`.
- Общие границы файлов: корневой `AGENTS.md`.

Пустой граф — отдельный проверяемый сценарий. Визуально проверьте `graph=null`, `graph-slice-empty.json` и обычный `graph-slice.json`: вместо пустого белого поля должно быть понятное сообщение.

## Светлая дизайн-система

- «Сеть переводов» занимает всю ширину страницы. Список приоритетов и карточка клиента встроены в её боковые стенки и независимо сворачиваются в узкие полосы с иконками и названиями. На экранах до 1100 px панели изначально закрыты и раскрываются по одной поверх графа; Escape или нажатие на затемнённую область закрывает панель. Поиск, фильтры и выбранный клиент сохраняются при сворачивании; клавиша `/` раскрывает приоритеты и переводит фокус в поиск.
- Высота рабочей области сети задана независимо от остальных блоков: 560–820 px в зависимости от высоты экрана, 580 px на телефоне. Раскрытие импорта или AI-дока увеличивает длину страницы, сохраняя высоту графа и боковых панелей. Списки и карточка прокручиваются внутри своих панелей.
- Акцент `#4FB84E` взят из интерфейса [Freedom Bank](https://bankffin.kz/ru/exchange-rates); крупные показатели основаны на [Broker](https://fbroker.kz/) и [Insurance](https://ffins.kz/ru), группировка формы — на [Travel](https://freedom-travel.kz/). Основной заголовок 30 px (26 px на компактном экране), заголовки панелей 16 px, показатели 26–32 px; вес заголовков и показателей 700. CoFo Sans задан первым в стеке; лицензированные файлы шрифта не входят в проект, поэтому при его отсутствии используется Segoe UI. Числа используют интерфейсный шрифт с табличными цифрами, gid и имена файлов — моноширинный.
- Полное значение сокращённой суммы в статистике доступно при наведении и фокусе; скринридер получает точное значение. Карточки имеют тонкую границу, радиус 12 px и не используют тени.
- Шесть цветов ролей взяты из палитры Paul Tol Muted. Роли различаются также формой узлов; переключение цвета по роли или кластеру обновляет легенду. Формы и настройки описаны в `src/features/graph/README.md`.
- Диаметр узла: `sqrt(6² + (18² − 6²) × clamp(priority_score, 0, 1))`. Seed и выбор меняют обводку, а не размер.
- Толщина ребра сохраняет P95-нормировку: `0.7 + 1.1 × min(1, log1p(max(sum_kzt, 0)) / log1p(max(P95, 1)))` с локальным обзорным коэффициентом 0.5. P95 вычисляется по рёбрам текущего среза с линейной интерполяцией. Стрелка находится у получателя; встречные переводы показаны отдельными кривыми.
- Раскладка рассчитывается в Web Worker и плавно стабилизируется. Регулируются притяжение к центру, отталкивание, сила и длина связей. Выбор узла не запускает раскладку повторно; поиск внешнего узла за пределами видимой области фокусирует его.
- Приоритет от 0.8 обозначается точкой и числом в списке; карточка показывает значение и тонкую шкалу. Цвет не является единственным обозначением высокого приоритета.
- Пять метрик вычисляются **по текущему GraphSlice**. В real-режиме это полный снимок `/api/analysis`, в mock — демонстрационный срез. Оборот — сумма рёбер между присутствующими узлами; компонента связности считается без учёта направления, включая изолированные узлы. Для пустого среза доли показываются как «—».
- AI-агент-чат — свёрнутый нижний док с раскрываемой заглушкой. Отправки сообщений и подключения модели нет.

## Проверки

```bash
npm test
npm run build
```

Тесты проверяют суммы, доли, слабую связность, пустые данные, P95, размеры узлов, локальную проверку Parquet, сочетание фильтров, потоки внутри среза и экранирование CSV. Тесты HTTP-адаптера и состояния дополнительно проверяют точные строковые int64, направления, изолированные узлы, multipart, ошибки и отмену запросов, версии анализа и сохранение графа. `synthetic-api.json` — только синтетическая сетевая фикстура для тестов, UI её не загружает. Дополнительные тестовые зависимости не нужны: используется Node test runner.

## Сценарии рабочего пространства

- Поиск фильтрует список по части `gid`. Enter выбирает точный `gid` и сбрасывает остальные фильтры; в real-режиме он запрашивает backend даже для идентификатора вне топ-20; `/` переводит фокус в поиск. Отсутствующий идентификатор даёт понятное сообщение.
- Кластер, роль и порог приоритета 0.8 работают совместно. Сортировка доступна по приоритету и рангу. Фильтры относятся к списку, граф и статистика относятся к текущему срезу.
- «Экспорт списка» формирует CSV только для видимых участников с учётом фильтров. В mock-режиме файл называется `top_nodes_demo.csv`. UTF-8 BOM и `;` рассчитаны на русскую локаль таблиц, формулы нейтрализуются, кавычки экранируются. При импорте в Excel указывайте текстовый тип колонки `gid`, чтобы редактор не округлил int64. Полные серверные экспорты доступны на backend `/api/exports/{name}`, но пока не подключены к кнопкам этого экрана.
- Карточка поддерживает копирование `gid`; при недоступности буфера можно выделить идентификатор вручную. Признаки и наблюдаемые суммы не подменяются данными другого участника.
- `useWorkspace.ts` управляет запросами и игнорирует устаревшие ответы при переключении узлов. Ошибки списка и карточки имеют независимые кнопки повтора.
- Граф загружается отдельным модулем через `React.lazy`. `ErrorBoundary` предлагает восстановление после ошибки отрисовки. После перезагрузки страницы real-режим получает активный анализ backend; выбор локальных файлов в форме не сохраняется.

## Что остаётся до реального использования

Импорт, расчёт и просмотр реального анализа подключены. В интерфейсе остаётся подключить три серверных экспорта и AI-док. Аутентификация, разграничение доступа и журнал действий относятся к следующему этапу.

## Импорт и подключение сервиса

`features/workspace/DataImport.tsx` содержит три независимых слота: `edges`, `nodes`, `transactions`. `ImportSlot.tsx` отображает состояния `empty`, `validating`, `selected`, `uploading`, `checking`, `ready`, `error`. Статус расчёта расположен отдельно. У слотов есть pulse, подтверждающая галочка, подсветка и однократное смещение текста ошибки; при `prefers-reduced-motion: reduce` анимации отключаются.

Локальная проверка в `importModel.ts` читает только начало и конец файла: расширение, размер, маркеры `PAR1` и границы метаданных. Она не проверяет колонки, типы или содержимое строк. Успешная локальная проверка даёт статус «Выбран», а не «Готов». Зашифрованный Parquet этой проверкой не поддерживается. Повторный выбор или удаление отменяет применение результата предыдущей проверки этого слота.

Для интеграции API-адаптер передаёт компоненту `DataImport` функцию `startImport` типа `StartImport` из `importModel.ts`. Она получает три `File`, callback событий и `AbortSignal`; отправляет пакет в согласованный API и сообщает подтверждённые статусы файлов и пайплайна. Callback `file` может передать фактический процент 0–100 либо оставить его неизвестным. `ready` означает подтверждённый приём и проверку файла; `running` и `complete` принимаются только после готовности всех файлов. Promise завершается после терминального события `complete`/`error`; при сетевой ошибке отклоняется. Все HTTP-запросы и чтение env остаются в `shared/api/`.

В real-режиме `useWorkspace` передаёт `startImport`: три поля multipart `nodes`, `edges`, `transactions` отправляются в `POST /api/analyze`. Endpoint синхронный, поэтому UI показывает «Отправка набора и расчёт…» без выдуманных процентов; готовность файлов подтверждается успешным ответом сервера, завершение — после получения нового `/api/analysis`. При ошибке загрузки предыдущий снимок остаётся доступен. В mock-режиме отправка отключена. Общий `shared/contracts.ts` не изменён.

## Реальный снимок и карточки

После запуска в real-режиме `GET /api/analysis` загружает все узлы, включая изолированные, исходные направленные рёбра и топ-20. `src`/`dst` отображаются в `source`/`target`; роли, кластеры и основания берутся из backend. Идентификаторы не преобразуются в `Number`. Карточка `GET /api/nodes/{gid}` отображает `in_kzt`, `out_kzt`, `in_deg`, `out_deg` и проверяет совпадение `analysis_id`. Выбор карточки сохраняет объект полного графа и его раскладку.

До первой загрузки показывается `NO_ANALYSIS`; неизвестный gid и сетевые ошибки дают понятное сообщение. При смене версии сервера карточка не смешивается со старым графом: используйте «Обновить анализ». Повторный расчёт атомарно заменяет снимок, а отменённые и устаревшие ответы игнорируются. При повторном чтении той же версии сохраняется объект графа.

## Приёмка на реальных данных — 23.09.2026

- Загрузка трёх исходных Parquet через UI завершилась расчётом: 2248 узлов, 3119 направленных рёбер и 88 кластеров.
- Программно проверены все 2248 строковых `gid`, направления всех 3119 рёбер, фильтры 88 кластеров и 6 ролей, а также 19 изолированных узлов.
- В UI проверены выбранные сценарии: поиск узла вне топ-20; поиск изолированного узла; явное раскрытие узла, скрытого фильтром изолятов или кластера; ответ backend для отсутствующего корректного int64 без потери графа. Для представителей всех 6 ролей сверены карточки, граф и кластеры с API. Узел `depth=4` без исходящих сохранил серверную роль `peripheral`. Взаимные переводы визуально показаны стрелками в обоих направлениях и сверены с API.
- `npm test`: 34/34 успешно; `npm run build`: успешно. Полная программная сверка идентификаторов и направлений не означает ручную проверку каждого узла и ребра в UI. AI-док и кнопки серверных CSV-экспортов не входили в эту приёмку.
