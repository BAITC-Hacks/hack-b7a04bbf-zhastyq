# Frontend «Граф денег»

React + TypeScript + Vite + Cytoscape. Существующая светлая тема, сворачиваемые панели и дизайн-токены сохранены. Интерфейс работает с настоящим backend; демонстрационной подстановки при ошибках нет. Общий запуск двух сервисов — [корневой README](../README.md).

## Локальная разработка

Требуется Node `>=24.11.0 <25`; `.nvmrc` — 24.11.0, lock-файл сохраняется. Проверено на Node 24.21.0 / npm 11.19.0. Из `frontend/`:

```bash
npm ci
npm test
npm run build
npm run dev
```

Адрес http://127.0.0.1:5173. Предварительно запустите backend на 127.0.0.1:8000 по его README. Vite проксирует `/api`, `/docs`, `/openapi.json` в backend. `npm run preview` раздаёт production-сборку с тем же локальным прокси. Это способ проверки без Docker, а не production-сервер.

Запросы по умолчанию относительные `/api/...`. `VITE_API_BASE_URL` может задать origin другого backend для отдельного размещения; в таком случае настройте CORS на backend. Vite-переменные применяются при сборке, после изменения пересоберите. Dockerfile фиксирует пустой base URL и `VITE_API_MOCK=false`; рабочий адаптер не использует mocks даже при другом значении этой переменной. JSON-фикстуры сохранены только для тестов.

## Сценарий

1. При отсутствии анализа выберите `nodes.parquet`, `edges.parquet`, `transactions.parquet`, затем «Загрузить и запустить». Локально проверяются расширение, размер ≤25 MiB и оболочка Parquet, на backend — колонки, значения и расчёт. Готовность показывается после подтверждения сервера и получения снимка.
2. Откроются top-20 с причинами и карточка первого приоритетного узла. При ошибке новой загрузки прежний анализ остаётся доступен.
3. Поиск точного gid + Enter работает по **всем** узлам, включая изолированные и отсутствующие в top-20. Фильтры списка относятся только к top-20.
4. Граф показывает выбранный узел, всех непосредственных соседей и рёбра между ними. Это подграф, не вся сеть; поиск полный. Стрелка у получателя; размеры узлов зависят от приоритета. Клик по узлу или связи в карточке меняет выбор.
5. Карточка содержит все входящие/исходящие связи, data_gaps с соответствующими next_requests и до 50 временных наблюдений; объяснения и ограничения доступны в раскрываемых элементах.
6. AI-помощник задаёт вопрос по выбранному узлу. Ответ — безопасный текст; ссылки открывают карточки. STALE_ANALYSIS обновляет снимок и предлагает повторить вопрос вручную. Автоматических повторных платных запросов нет.
7. Кнопки `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` скачивают серверные CSV. Версия проверяется через X-Analysis-Id, при смене анализа предлагается обновление.

Все gid — строки. При смене analysis_id карточки, фильтры и старые AI-ответы очищаются. Старые HTTP-запросы карточек/AI отменяются. Ошибки сети показываются с возможностью повтора; фиктивный gid 1005 в рабочем сценарии не используется.

## Устройство и проверки

`shared/api/workspace.ts` — единственный HTTP-адаптер и преобразование полей; `shared/api/types.ts` — типы реального контракта. `useWorkspace` хранит согласованный снимок. `GraphView` получает props, не делает HTTP-запросов. [Точный контракт](../backend/docs/data_contract.md).

- `npm test`: unit-тесты графа, импорта, списка и API-адаптера с mock-fetch; внешняя LLM не вызывается.
- `npm run build`: TypeScript и production Vite.
- `tests/browser-smoke.mjs`: реальный Chromium/HTTP на исходном датасете. Все AI-запросы перехватываются fake-ответом, даже если backend настроен с ключом. Запуск требует отдельного Playwright и его Chromium, включённого backend и собранного сайта. Пример без изменения зависимостей frontend из корня репозитория:

```bash
mkdir -p backend/.tmp/browser-check
npm install --prefix backend/.tmp/browser-check --no-audit --no-fund playwright
backend/.tmp/browser-check/node_modules/.bin/playwright install chromium
PLAYWRIGHT_MODULE="$PWD/backend/.tmp/browser-check/node_modules/playwright/index.mjs" \
APP_URL=http://127.0.0.1:8080 DATA_DIR="$PWD/backend/data" \
SMOKE_OUTPUT="$PWD/backend/.tmp/browser-smoke" node frontend/tests/browser-smoke.mjs
```

В ОС должны быть библиотеки Chromium. Скрипт загружает/заменяет активный анализ: запускайте против отдельного тестового экземпляра. Скриншот, отчёт и скачанные CSV пишутся в исключённый из Git каталог. Это smoke-тест выданного датасета; unit-тесты от него не зависят. [Фактический протокол интеграции](../backend/docs/integration.md).
