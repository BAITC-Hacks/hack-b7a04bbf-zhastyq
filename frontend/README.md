# Фронтенд AML MVP

React + TypeScript + Vite + Cytoscape.js, обычный CSS. Одноэкранный интерфейс подключён к HTTP API модульного монолита.

## Запуск

Node.js `24.11.0` (см. `.nvmrc`), npm `11.6.1`. Из `frontend/`:

```bash
npm install && npm run dev
```

Для воспроизводимой установки используйте `npm ci`. По умолчанию включён **реальный API**. До загрузки данных отображается пустое состояние; при недоступности бэкенда — ошибка с повтором.

Бэкенд запускается отдельно, из `backend/` (Python 3.10+; команды для PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn money_graph.bootstrap:create_api_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

Vite проксирует `/api` на `http://127.0.0.1:8000`; браузер открывает `http://127.0.0.1:5173`. Swagger: `http://127.0.0.1:8000/docs`. Для другого порта/домена скопируйте `.env.example` в `.env` и задайте `VITE_API_BASE_URL`. При прямых запросах на другой origin включите origin фронтенда в backend `CORS_ORIGINS`. После изменения env перезапустите Vite.

Для AI скопируйте `backend/.env.example` в `backend/.env`, настройте серверные параметры согласно `backend/README.md` и добавьте к команде uvicorn `--env-file .env`. Ключи никогда не помещаются в `VITE_*`. Без настроенного AI остальной анализ работает.

В собранном приложении настройте reverse proxy для `/api` либо задайте полный `VITE_API_BASE_URL` **до сборки**. Dev proxy Vite не входит в production bundle. Бэкенд пока рассчитан на локальное использование: один worker, общий снимок в памяти, без аутентификации. После его перезапуска набор надо загрузить заново.

## Фактический API

Каноническая спецификация: `backend/docs/data_contract.md`. Предварительные URL в `ARCHITECTURE.md` и заданиях агентов исторические; интеграция использует маршруты ниже. Общий `src/shared/contracts.ts` и файлы заданий не изменены.

| Endpoint | Использование |
| --- | --- |
| `GET /api/health` | Доступность, готовность анализа и конфигурация AI |
| `POST /api/analyze` | Три multipart-поля `nodes`, `edges`, `transactions`; ответ после расчёта |
| `GET /api/analysis` | Полный снимок: узлы, рёбра, кластеры, топ, сводка |
| `GET /api/nodes/{gid}` | Метрики клиента, связи, ограничения, пробелы и запросы для проверки |
| `GET /api/exports/{name}` | `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` |
| `POST /api/ask` | Вопрос по текущему `analysis_id` и выбранному клиенту |

Все HTTP-запросы и env собраны в `src/shared/api/`. Wire DTO находятся в `src/shared/api/types.ts`; адаптация к неизменному GraphView — в `features/workspace/analysisModel.ts`. Идентификаторы int64 остаются строками при поиске, сопоставлении и отправке. Ошибки `{error:{code,message,details}}` показываются в контексте операции; устаревшие запросы отменяются.

`VITE_API_MOCK=true` явно включает синтетические JSON-фикстуры. Полная демо-карточка и граф есть для gid 1005. В деморежиме отправка файлов и AI отключены. Автоматического перехода на демоданные при сбое сервиса нет.

## Сценарий аналитика

1. Раскрыть импорт и выбрать/перетащить три Parquet. Локально проверяются расширение, размер до 25 МиБ, маркеры PAR1 и границы метаданных. Это проверка оболочки, а не колонок.
2. «Загрузить и запустить» отправляет единый набор. API синхронный: точного процента или job polling нет. Слоты показывают ожидание ответа, становятся готовыми после успешного ответа; статус расчёта отдельно подтверждается получением снимка. Ошибка с `details.file` подсвечивает соответствующий слот. Неудачная загрузка сохраняет предыдущий анализ.
3. Статистика считается по **всему анализу**, включая изолированные узлы; оборот — по всем рёбрам, компонента — слабая связность. Текущий `analysis_id` и число транзакций видны над статистикой.
4. Поиск доступен по всем узлам, включая отсутствующие в серверном top. Enter выбирает точный gid; клавиша `/` раскрывает список и фокусирует поиск. Кластер, роль и порог 0.8 фильтруют список совместно. Список выводится порциями по 40; фильтры и поиск используют полный набор.
5. Граф показывает выбранный центр и до 120 непосредственных соседей с наибольшим суммарным оборотом в обоих направлениях. Все направленные связи между показанными узлами сохраняются. При ограничении есть явное количество и кнопка расширения. Выбор соседа сохраняет текущую раскладку; отдельная кнопка открывает его собственное окружение.
6. Карточка получает полные метрики из API независимо от размера графа. Ограничения наблюдения, пробелы в данных и следующие запросы показаны отдельными раскрываемыми блоками.
7. Экспорт предлагает три **серверных** CSV и дополнительный текущий отфильтрованный список. Серверный заголовок `X-Analysis-Id` проверяется перед скачиванием. При импорте CSV в Excel задайте текстовый тип колонки gid, чтобы не округлить int64.
8. AI-док раскрывается снизу. Вопрос отправляется только по кнопке; ответ — обычный текст, ссылки на клиентов и ограничения. Отмена прекращает ожидание в браузере, но сервер мог продолжить запрос. Устаревший анализ обновляется без автоматического повторного AI-вызова.

Обновление страницы восстанавливает текущий снимок сервера. Выбранные локальные файлы не сохраняются. Кнопка «Обновить» получает актуальную версию после расчёта другим пользователем.

## Интерфейс и владение файлами

Дизайн-токены `src/styles/tokens.css` импортируются первыми в `src/main.tsx`; ими владеет агент 1. Светлая зелёно-бело-чёрная тема, компактный приоритет, тонкие границы. По прямому указанию пользователя от 23.09.2026 агент приложения также дорабатывает модуль графа после завершения работы второго агента. Общий контракт данных сохранён.

Подписи графа рисуются отдельным слоем с фиксированным шрифтом 12 px. Полный gid показан для выбранного узла и при наведении; если вокруг тесно, подпись выносится на свободное место с пунктирной линией. Дополнительно выводится до 12 непересекающихся подписей с различимыми в срезе суффиксами. Переключатель «Подписи» управляет дополнительными подписями; кнопки −/+ меняют масштаб, «Весь срез» возвращает обзор. Стрелки переводов сохраняются, их размер и толщина рёбер ограничены при увеличении. Плотность CoSE учитывает размер среза и число связей центральных узлов; выбор клиента сохраняет раскладку.

Сеть занимает всю ширину. Боковые панели независимо сворачиваются в узкие стенки; до 1100 px раскрываются по одной поверх графа и закрываются по Escape. Высота графа независима от импорта и AI-дока: их раскрытие удлиняет страницу. Локальные списки и карточки прокручиваются внутри панелей. Анимации импорта учитывают `prefers-reduced-motion`.

Роли и приоритеты — гипотезы для проверки, не выводы о виновности. Реальные результаты не заменяются фикстурами при ошибках.

## Проверки

```bash
npm test
npm run build
```

Node test runner проверяет API и ошибки через локальные mock fetch, сохранность int64, ограничение окружения, изолированные узлы, статистику полного снимка, фильтры, Parquet и CSV. Внешние AI-запросы тесты не выполняют.

Из `backend/`:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
```

Ручная приёмка: пустой сервер → три валидных Parquet → расчёт → поиск длинного gid → карточка/граф → три CSV → повторная загрузка с неверными колонками (предыдущие результаты сохранены) → перезагрузка страницы. Отдельно проверить недоступный сервис и AI без конфигурации. Платный ответ AI проверяется отдельно при настроенном сервере и явной отправке вопроса.

Проверено 23.09.2026: 263 backend-теста, 33 frontend-теста, production-сборка и Ruff проходят. Через настоящий HTTP-сервер выполнены 49 проверок маршрутов и ошибок. Браузерный сценарий пройден на валидном синтетическом Parquet-наборе (4 узла, 3 ребра, 4 операции): импорт, расчёт, точный int64, изолированный клиент, три CSV, ошибка обязательной колонки с сохранением результата, отключение/восстановление сервера, пустое состояние, AI без конфигурации. Высота сети при раскрытии импорта остаётся 560 px в проверенном desktop viewport. Реальный датасет из 2 248 клиентов и внешний AI-провайдер в этой приёмке не использовались.

После доработки графа: 41 frontend-тест и production-сборка проходят. На уже загруженном реальном наборе из 2 248 клиентов отдельно проверен срез из 86 узлов и 88 связей: увеличение до 400% сохраняет шрифт подписей 12 px без пересечений; отключение дополнительных подписей оставляет полный gid выбранного узла; клик по узлу обновляет карточку, а «Весь срез» возвращает обзор. Тесты размещения подписей покрывают плотные центры, одинаковые суффиксы int64, границы viewport, изменение масштаба и выноски.
