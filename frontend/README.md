# Фронтенд AML MVP

Одноэкранный интерфейс аналитика: загрузка Parquet, топ приоритетов, поиск `gid`, направленный граф и карточка узла. Бэкенд команды — модульный монолит с одним HTTP API.

## Локальный запуск

Используйте Node.js `24.11.0` из `.nvmrc` и npm `11.6.1`. Из каталога `frontend/`:

```bash
npm install && npm run dev
```

Команда поднимает одноэкранное приложение со светлыми панелями и демонстрационными данными. Подробная карточка и граф доступны для gid 1005. Выбор файлов пока не запускает анализ: подключение сервиса анализа и реального API — отдельный этап. При выключенном mock-режиме отображается сообщение о неподключённом сервисе, синтетические результаты не подставляются.

Дизайн-токены находятся в `src/styles/tokens.css` и импортируются первыми в `src/main.tsx`. Файлом владеет агент 1. Агент 2 читает глобальные `--graph-*` и `--role-*` при оформлении графа.

Для воспроизводимой установки по зафиксированному `package-lock.json` можно использовать `npm ci` вместо `npm install`.

## API и mock-режим

Без `.env` приложение запускается в mock-режиме. Для явной настройки скопируйте `.env.example` в `.env`. `VITE_API_MOCK=true` означает работу со статичными синтетическими фикстурами в `src/shared/api/fixtures/`; `false` зарезервирован для подключения API по `VITE_API_BASE_URL`, которое пока не реализовано. Обе переменные читает только API-адаптер. После изменения `.env` перезапустите dev-сервер. Подробная фикстура подготовлена для `gid=1005`. Выбор его соседей сохраняет показанный срез, но не подставляет чужую карточку; выбор клиента вне среза показывает отсутствие данных.

Предварительные маршруты и типы описаны в `ARCHITECTURE.md` и `src/shared/contracts.ts`. Если фактические маршруты модульного монолита отличаются, меняйте только `src/shared/api/`.

## Передача работы между агентами

- Агент 1: `AGENT_APP.md` — экран, сценарий, API, mock/real переключатель.
- Агент 2: `AGENT_GRAPH.md` — только `src/features/graph/`.
- Общие границы файлов: корневой `AGENTS.md`.

Пустой граф — отдельный проверяемый сценарий. Визуально проверьте `graph=null`, `graph-slice-empty.json` и обычный `graph-slice.json`: вместо пустого белого поля должно быть понятное сообщение.

## Светлая дизайн-система

- Три колонки сохранены: список, граф, карточка. Интерфейс рассчитан на настольный экран от 1024 px; списки и карточка прокручиваются внутри панелей.
- Шесть цветов ролей взяты из палитры Paul Tol Muted. Все узлы круглые; названия ролей доступны в легенде и карточке.
- Диаметр узла: `sqrt(6² + (18² − 6²) × clamp(priority_score, 0, 1))`. Seed и выбор меняют обводку, а не размер.
- Толщина ребра: `0.7 + 1.1 × min(1, log1p(max(sum_kzt, 0)) / log1p(max(P95, 1)))` px. P95 вычисляется по рёбрам текущего среза с линейной интерполяцией. Маленькая стрелка находится у получателя.
- Раскладка — CoSE без анимации: длина связей внутри кластера 42, между кластерами 84. Выбор узла не запускает раскладку повторно; изменение размера панели подстраивает камеру.
- Приоритет от 0.8 обозначается точкой и числом; карточка дополнительно получает тонкую боковую полосу.
- Пять метрик вычисляются **только по текущему GraphSlice**, не по всей базе из 2248 клиентов. Оборот — сумма рёбер между присутствующими узлами; компонента связности считается без учёта направления, включая изолированные узлы. Для пустого среза доли показываются как «—».
- AI-агент-чат — свёрнутый нижний док с раскрываемой заглушкой. Отправки сообщений и подключения модели нет.

## Проверки

```bash
npm test
npm run build
```

Тесты проверяют суммы, доли, слабую связность, пустые данные, P95 и размеры узлов. Дополнительные тестовые зависимости не нужны: используется Node test runner.
