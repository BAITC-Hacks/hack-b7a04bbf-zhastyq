# Задание агенту 1: приложение и сценарий аналитика

Ты владеешь оболочкой React-приложения, API-адаптером и всем пользовательским сценарием вне графа. Прочитай корневой `AGENTS.md`, `frontend/ARCHITECTURE.md` и `frontend/src/shared/contracts.ts`.

## Сделать

1. Использовать уже подготовленные `package.json`, `package-lock.json`, `.nvmrc`, `.env.example` и README. Создать недостающие файлы Vite + React + TypeScript внутри существующей папки `frontend/`, не удаляя её содержимое.
2. Собрать один экран: загрузка трёх Parquet-файлов, статус анализа, топ не менее 20 узлов, поиск по `gid`, карточка узла, ссылки на три CSV.
3. Реализовать API-адаптер только в `src/shared/api/`. Он единственный читает `VITE_API_MOCK` и `VITE_API_BASE_URL`. Если `VITE_API_MOCK` не задан, включить mock по умолчанию. При mock-режиме возвращать подготовленные `fixtures/*.json`; при real-режиме обращаться к единому API бэкенда. Показывать в UI плашку «Демонстрационные данные» через признак адаптера, не читая env в компонентах. Подробная фикстура есть для `gid=1005`; при выборе других `gid` не подставлять его данные.
4. Хранить выбранный `gid` и текущий `GraphSlice` в состоянии приложения. При выборе узла из списка, поиска или callback графа обновлять карточку и граф.
5. Импортировать `GraphView` из `src/features/graph/GraphView.tsx` и передать props строго по `GraphViewProps`. Пока агент 2 работает, временная заглушка может находиться только в твоей папке; не создавай и не правь файлы в `features/graph/`.
6. Дополнить `frontend/README.md` фактически работающими командами и настройками. Проверить `npm run build` и вручную пройти сценарий: загрузка → топ → поиск → карточка → связи → CSV.
7. Проверить пустой ответ `GraphSlice`: UI должен показать ясное сообщение, сохранить работающий поиск и не выдавать синтетические связи за реальные.

## Не трогать

`frontend/src/features/graph/**`, `frontend/src/shared/contracts.ts`, `frontend/AGENT_GRAPH.md`.

## Результат

Готовый пользовательский сценарий, который работает с API-контрактом из архитектуры. В итоговом сообщении перечисли изменённые файлы, результат сборки и любые несовпадения с бэкендом.
