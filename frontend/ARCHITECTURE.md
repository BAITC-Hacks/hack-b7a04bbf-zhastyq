# Архитектура фронтенда MVP

## Стек и граница модулей

- React + TypeScript + Vite: одноэкранное локальное приложение.
- Cytoscape.js: отрисовка ориентированного графа. Подключается только внутри `src/features/graph/`.
- Обычный CSS. Глобальные стили принадлежат агенту 1; граф использует свой CSS module или стили в своей папке.
- Нативный `fetch`: запросы к бэкенду собраны в `src/shared/api/`, которым владеет агент 1.
- Общие типы находятся в `src/shared/contracts.ts` и фиксированы для параллельной работы.
- Бэкенд строится как модульный монолит. Фронтенд видит один HTTP API и не зависит от разбиения его внутренних модулей.

Поток данных: `API → API-адаптер → состояние App/Workspace → GraphView`. Граф получает готовый срез сети через props и сообщает о клике на узел callback. Он не делает HTTP-запросов и не хранит состояние выбранного `gid` как источник истины.

## Экран

1. Сверху: загрузка `edges.parquet`, `nodes.parquet`, `transactions.parquet` и состояние расчёта.
2. Слева: топ минимум 20 узлов, поиск по `gid`, фильтр кластера.
3. В центре: `GraphView` с направлением переводов, цветами ролей и выделением выбранного узла.
4. Справа: карточка узла с ролью, приоритетом и объяснением. Текст — гипотеза для проверки.
5. Скачивание `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`.

После выбора `gid` приложение запрашивает локальный срез графа вокруг него. Не выводите все 2 248 узлов сразу: поиск, выбранный кластер и окружение узла дают читаемую картину. Если данных пока нет, UI показывает пустое состояние; не выдавайте фиктивные результаты за реальные.

## Контракт интеграции

Точный контракт компонента `GraphView` задан типом `GraphViewProps` в `src/shared/contracts.ts`. Агент 2 экспортирует компонент по умолчанию из `src/features/graph/GraphView.tsx`. Агент 1 импортирует его в `App.tsx` или `features/workspace/` и передаёт `graph`, `selectedGid`, `loading`, `onSelectGid`.

Предварительный HTTP-контракт для адаптера агента 1; уточняется с бэкендом без изменений компонентов:

| Запрос | Ответ |
| --- | --- |
| `POST /api/analyses` с тремя Parquet-файлами | `{ analysis_id, status }` |
| `GET /api/analyses/{id}` | `{ status, error? }` |
| `GET /api/analyses/{id}/top?limit=20` | `TopNode[]` |
| `GET /api/analyses/{id}/nodes/{gid}` | `NodeDetails` |
| `GET /api/analyses/{id}/graph?gid={gid}&hops=1` | `GraphSlice` |
| `GET /api/analyses/{id}/exports/{name}` | CSV-файл; `name` — один из трёх выходных файлов |

`gid` передаётся в JSON строкой: в исходных Parquet это `int64`, который может выходить за пределы точного целого JavaScript. Если бэкенд использует другие URL, меняется только API-адаптер, а не компоненты.

## Работа до готовности бэкенда

- `VITE_API_MOCK=true` включает статичные JSON-фикстуры из `src/shared/api/fixtures/`. При `false` адаптер отправляет реальные запросы. Если переменная не задана, режим по умолчанию — mock, чтобы команда запуска работала без `.env`. Переменную читает только `src/shared/api/`; адаптер может вернуть UI признак демонстрационных данных для явной плашки, но компоненты не читают env напрямую.
- `VITE_API_BASE_URL` задаёт адрес единого API модульного монолита. Он применяется только в API-адаптере, без `localhost:8000` в компонентах.
- Оба значения перечислены в `.env.example`. Локальный `.env` не коммитится. После изменения `.env` нужно перезапустить Vite. Если выбран real-режим без `VITE_API_BASE_URL`, показать понятную ошибку конфигурации.
- `top-nodes.json`, `node-details.json`, `graph-slice.json` — синтетические данные для сборки сценария на `gid=1005`. `graph-slice-empty.json` нужен для проверки пустого состояния. Эти файлы не содержат результатов реального датасета. Для остальных `gid` mock-адаптер должен явно сообщать, что подробная фикстура отсутствует, вместо показа чужой карточки или графа.
- Для переключения на бэкенд поставить `VITE_API_MOCK=false` и задать его фактический URL в `VITE_API_BASE_URL`; компоненты менять не требуется.

## Готовность MVP

- Загрузка и повторный расчёт не требуют перезагрузки страницы.
- Поиск точного `gid` открывает карточку и его связи.
- На каждом ребре видно направление; цвет узла соответствует легенде ролей.
- Топ показывает приоритет и короткое объяснение.
- Ошибка API и отсутствие данных имеют понятные состояния.
- `GraphView` визуально проверен с `graph=null`, `graph-slice-empty.json` и непустой фикстурой. В пустом состоянии виден текст, а не белое поле или ошибка.
- Фронтенд собирается командой `npm run build`.
