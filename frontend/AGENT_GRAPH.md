# Задание агенту 2: визуализация сети

Ты владеешь только модулем `frontend/src/features/graph/`. Прочитай корневой `AGENTS.md`, `frontend/ARCHITECTURE.md` и `frontend/src/shared/contracts.ts`. Работай параллельно с агентом 1 без изменений его файлов.

## Сделать

1. Создать `GraphView.tsx` с default export компонента, принимающего ровно `GraphViewProps`.
2. Отрисовать `GraphSlice` через Cytoscape.js: узлы по ролям, стрелка от `source` к `target`, легенда ролей, выделение `selectedGid`.
3. При клике на узел вызвать `onSelectGid(gid)`. При смене `graph` обновить элементы; при размонтировании освободить экземпляр Cytoscape.
4. Показать состояния загрузки, пустого графа и отсутствующего выбранного узла. Для окружения из нескольких десятков/сотен узлов выбрать читаемую раскладку; не включать тяжёлую анимацию всего графа.
5. Размещать локальные стили и вспомогательные функции только в `src/features/graph/`.
6. Проверить компиляцию своего модуля после появления Vite-оболочки. Сообщить агенту 1 точный путь импорта и результат проверки.
7. Для локальной проверки использовать синтетические `src/shared/api/fixtures/graph-slice.json` и `graph-slice-empty.json`. Проверить визуально три случая: `graph=null`, пустые `nodes/edges`, непустой граф. В первых двух должен быть видимый текст состояния, а не пустое белое поле; ошибок в консоли быть не должно. В production-компонент фикстуры не импортировать. Не отмечать работу законченной до этой визуальной проверки.

Бэкенд команды — модульный монолит с одним HTTP API. Твой компонент не знает его URL, маршруты и состояние загрузки данных: всё приходит через `GraphViewProps`.

## Не трогать

`frontend/package.json`, `frontend/src/App.tsx`, `frontend/src/main.tsx`, `frontend/src/features/workspace/**`, `frontend/src/shared/**`, `frontend/src/styles/**`.

## Результат

Изолированный `GraphView`, который можно подключить одним импортом и который не зависит от API или внутреннего состояния приложения. В итоговом сообщении перечисли изменённые файлы и результат проверки.
